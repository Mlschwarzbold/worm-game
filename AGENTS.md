# Worm Game — Agent Guide

## Project Overview

A graph-based puzzle game where the player navigates a worm through a network of connected nodes. The worm grows by eating food nodes and must reach the end node after consuming all food.

**Stack:** Vanilla HTML/CSS/JS, SVG rendering, no build tools or frameworks.

## File Structure

| File | Purpose |

| `Dockerfile` | Two-stage build: node generates manifest, nginx serves static files |
| `Jenkinsfile` | CI/CD pipeline — builds Docker, deploys on port 6000 |

## Gameplay Rules

1. Worm starts at the `start` node (length 1)
2. Click an adjacent unoccupied node to move the head there
3. Landing on a `food` node consumes it and increases `wormLength` by 1
4. When `wormLength > wormPath.length`, the worm grows (tail stays in place)
5. When at max length, the worm slides (old tail drops, new head prepended)
6. **Win:** Head reaches `end` node AND all food consumed
7. **Stuck:** No reachable unoccupied neighbors — retry button turns red

## Key Data Structures

### `gameState`

```js
{
  levelIndex,        // Current level (0-based)
  currentLevel,      // { id, name, nodes[], edges[] }
  nodeMap,           // Map<nodeId, node>
  graphEdges,        // Set<"a-b"> (sorted edge keys)
  neighbors,         // Map<nodeId, Set<neighborId>>
  isLevelWon,        // Boolean
  wormLength,        // Target length (grows on food)
  wormPath,          // Array<nodeId> — index 0 = head
  animation,         // { oldPath, isGrowing, t, startTime, duration } or null
  lastEyeDir         // { x, y } normalized direction for idle eyes
}
```

### `proximityState`

```js
{
  nodeCircles,       // Array<{ id, x, y, el }> — cached node references
  highlightCircle,   // SVG circle for proximity highlight
  svg,               // Reference to #graph SVG
  onNodeClick        // Click handler callback
}
```

## Rendering Pipeline

### SVG Layer Order (bottom to top)

1. **`edges-layer`** — Graph edges (`stroke-width: 3`, gray)
2. **`nodes-layer`** — Node circles (`r=14`, white stroke, colored by type)
3. **`labels-layer`** — Node ID text labels
4. **Proximity highlight** — Single circle (`r=18`, green or gray outline)
5. **`worm-layer`** — All worm elements (appended last, on top)

### Worm Rendering Sub-Order (back to front)

1. Body edges (`stroke-width: 38`, black)
2. Body/tail circles (`r=19`, black fill, no stroke)
3. Animation lines (tail ghost line, head-to-body line — only during animation)
4. **Head circle** (`r=19`, black fill, white stroke)
5. **Eyes** (two `r=4` white circles, positioned by movement direction)

### Key Rendering Functions

- `renderGraph(svg, data, state, onNodeClick)` — Clears SVG, builds all layers, calls `renderWorm`
- `renderWorm(svg, data, path, anim)` — Builds worm-layer contents

## Animation System

### Timing

- Duration: 500ms per move
- Easing: `easeInOutCubic(t)` — slow start, fast middle, slow end
- Frame loop: `requestAnimationFrame` via `tick(now)`

### How Ghost Nodes Work

When the worm moves, `anim.oldPath` stores the previous path. Each frame:

- **Head:** Interpolates from `oldPath[0]` to `path[0]` via `lerp(old, new, t)`
- **Tail (non-growing):** Old tail fades out; a ghost position interpolates from old tail to new tail. A line is drawn from the real new tail to the ghost position.
- **Body nodes:** Remain static at their graph positions — no interpolation.
- **Eyes:** Follow the head; direction computed from movement vector.

### Eye Direction Logic

- **During animation:** Direction from `oldPath[0]` toward interpolated head position
- **Idle:** Uses `gameState.lastEyeDir` (cached from last move)
- **Level start:** Defaults to `{ x: 0, y: -1 }` (looking up)
- Reset on `loadLevel()`

## Level Format

```js
window.WORM_LEVELS.push({
  id: "level-1",
  name: "Display Name",
  nodes: [
    { id: "A", x: 141.8, y: 290.0, type: "start" },  // exactly 1 start
    { id: "B", x: 254.0, y: 242.9, type: "normal" },
    { id: "C", x: 358.9, y: 305.3, type: "food" },    // 0+ food
    { id: "E", x: 603.1, y: 321.6, type: "end" }      // exactly 1 end
  ],
  edges: [["A", "B"], ["B", "C"], ["C", "E"]]
});
```

**Constraints:** Unique node IDs, exactly 1 start, exactly 1 end, no duplicate edges, all edge references valid.

**Adding levels:** Create `levels/level-N.js`, then run `node scripts/generate-level-manifest.js` to update `manifest.js`.

## Proximity Interaction

- Nodes within 60px of the mouse get a white glow (intensity proportional to closeness)
- The closest node within range gets a colored outline:
  - **Green** (`#22c55e`) if reachable (valid move)
  - **Gray** (`#999999`) if not reachable
- Clicking anywhere on the SVG (background/edges) moves to the closest reachable node within range

## Custom Level Page

`custom.html` lets players import and play custom levels without modifying the codebase.

- **Import:** Paste JSON text or upload a `.json` file (format: `{id, name, nodes[], edges[]}`)
- **Validation:** Checks required fields, unique node IDs, exactly 1 start, valid edges, no duplicates
- **Storage:** Saved to `localStorage` under key `worm-custom-levels`
- **Play:** Loads the level into the game engine via `init([level])`
- **Persistence:** Saved levels survive page reloads; can be deleted from the list

The custom page sets `window.WORM_CUSTOM_PAGE = true` before `app.js` loads to prevent auto-init. It then calls `init([level])` with the custom level array when the user clicks Play.

## Playtest Page

`playtest.html` provides a quick way to test a level from the editor without leaving the browser.

- Editor saves current level to `sessionStorage` under key `worm-playtest-level`
- Opens `playtest.html` in a new tab (editor stays open)
- Playtest page reads the level and calls `init([level])`
- "Back to Editor" button returns to `editor.html`
- Uses `sessionStorage` (not localStorage) so test data is ephemeral

## Common Pitfalls

- **SVG rendering order:** Elements appended later appear on top. The head and eyes MUST be the last elements in `worm-layer`.
- **CSS class order:** `.worm-head` must appear after `.worm-node` in the stylesheet so its `stroke` override takes effect (same specificity).
- **Animation state:** Always check `hasAnim = anim && anim.oldPath` before accessing animation properties. The `animation` field is set to `null` when not animating.
- **Length-1 worms:** Tail animation must be guarded with `path.length > 1`. No body edges exist when path has 1 node.
- **Confetti canvas:** Must be `display: none` by default, only shown via `.active` class during win animation. High `z-index` would otherwise cover the SVG.
